# Progress

## Phases

| Phase | Status | Summary |
| ----- | ------ | ------- |
| Phase 0 — Research and workspace bootstrap | `Complete` | StarRocks source research completed and written up in [`RESEARCH.md`](./RESEARCH.md), covering the mechanisms adopted, those deliberately rejected, and the reasoning for each. A ten-crate cargo workspace was bootstrapped with crate boundaries drawn deliberately along the two seams that matter: the frontend/backend split and the row-format/column-format storage split, so that both remain deployment and routing choices rather than rewrites. `htap-common` carries the shared MVCC `Version` domain and the `FencingToken` type, together with the common error enum — these are shared by every other crate and so were built first. `ci.sh` runs `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo build --workspace` and `cargo test --workspace`; all four stages are green on a clean rebuild. |
| Phase 1 — Row store | `Complete` | Built the LSM row-store engine (`htap-rowstore`) with WAL, memtable, immutable SSTs, manifest tracking, snapshot isolation, and point lookups. Covered by unit tests, integration tests, bounded property-based reference model tests, and process-level crash tests: `wal_recovery` (record framing, torn-tail repair, atomicity, GC), `wal_crash` (`kill_9_loses_no_committed_data`, `a_cleanly_exiting_child_recovers_every_commit`), `sst` (block index, Bloom filter, multi-block iter, CRC corruption detection), `engine` (`test_commit_and_snapshot_visibility`, `test_reopen_preserves_data_and_version`, `test_first_writer_wins_conflict`, `test_delete_resurrection_regression`, `test_auto_flush_and_manual_flush`, `test_flush_then_reopen_empty_wal`), `mvcc_properties` (`prop_mvcc_engine_matches_model` proving snapshot stability, no future visibility, delete correctness, first-writer-wins, and recovery equivalence), and `engine_crash` (`engine_kill_9_recovers_all_reported_commits`, `engine_cleanly_exiting_child_recovers_every_commit`). |
| Phase 2 — Column store | `Complete` | Built the columnar storage engine (`htap-colstore`) with immutable binary segment layout, plain and dictionary encodings, optional zstd compression, CRC32C frame and footer checksums, typed per-block zone maps (min/max/nullability), and vectorized scans with selective column decoding and conservative pushdown pruning. Covered by unit tests, segment roundtrip and corruption tests (`crates/htap-colstore/tests/segment_roundtrip.rs`), vectorized scan reference tests (`crates/htap-colstore/tests/scan.rs`), and deterministic zone-map pruning acceptance test (`crates/htap-colstore/tests/zone_map_skip.rs`). |
| Phase 3 — SQL layer | `Complete (local MVP)` | Completed local slice: sqlparser MySQL dialect parsing, strict catalog binder with typed `PointSelect` and `AnalyticSelect`, structural route classifier (`Route::RowstorePointRead`, `Route::RowstoreWrite`, `Route::CatalogDdl`, `Route::OlapScan`), and durable catalog-backed synchronous `LocalServer` executing across unpartitioned tables (SQL `CREATE TABLE`) and partitioned tables created via native non-SQL API `LocalServer::create_partitioned_table` (finite Range/List topology). Supports multi-row `INSERT` routing across partitions in one commit version/payload, complete-PK `DELETE` and `SELECT` routed by partition key (preserving rowstore fast path), and narrow analytical scans over logical rowstore and base-plus-delta rows across all partitions using server-root `<root>/colstore` for materialized `Column`/`Converting` partitions with projection-aware compact reads (PK+requested column union, single safe predicate-leaf SegmentReader pushdown, delta suppression/overlay, deterministic PK ordering, and full residual SQL filter/aggregate/group evaluation; internal `ScanStats`/pruning evidence; logical rows used in SQL, vectorized aggregation deferred; conservative finite range/list partition pruning, bounded in-process partition scan workers, and deterministic global merge/order are implemented for narrow local OLAP; distributed fanout, disk spilling, query cancellation, and resource quotas remain deferred) with reopen recovery and `EmbeddedClient` façade. Parser boundary verified: MySQL `CREATE TABLE ... PARTITION BY RANGE ...` and `PARTITION BY LIST ...` return `HtapError::InvalidArgument` under sqlparser 0.62 / MySqlDialect because the parser does not retain MySQL partition definitions, and manual `partition_by` ASTs are rejected by the binder with `HtapError::Unsupported` with no lossy reinterpretation of unrelated AST nodes. Catalog enforces non-null PK partition keys, half-open `[lower, upper)` range bounds, exact list values, and validates overlaps/duplicates/types. Format conversion is guarded to single-partition tables. Covered by tests in `crates/htap-server/tests/local_server.rs` (including `test_partitioned_native_range_topology_catalog_reopen_continuation`, `test_partitioned_native_list_topology_catalog_reopen_continuation`, `test_partitioned_boundary_unmatched_null_type_errors`, `test_partitioned_multi_row_insert_spanning_partitions_one_version_point_delete`, `test_partitioned_composite_pk_partition_key_not_first`, `test_partitioned_olap_across_partitions_and_empty_aggregate`, `test_partition_pruning_range_and_list_and_conservative_cases`, `test_scan_worker_count_equivalence`, `test_multi_partition_order_by_directions_nulls_and_tie_breaking`, `test_convert_table_multi_partition_guard`, `test_partitioned_empty_topology_rejection_no_catalog_mutation`), `crates/htap-catalog/tests/catalog_recovery.rs` (`test_partitioning_legacy_decode_and_reopen`, `test_range_partitioning_routing_and_boundaries`, `test_list_partitioning_routing`, `test_partitioning_duplicate_violations`, `test_range_overlap_and_order_violations`, `test_partitioning_type_and_null_violations`, `test_partitioning_ownership_and_method_consistency`, `test_partitioning_cas_and_reopen_lifecycle`), `crates/htap-sql/tests/parse_bind.rs` (including `test_mysql_partition_ddl_rejected_at_parser_level` and `test_negative_create_table`), `crates/htap-sql/tests/route.rs`, `crates/htap-client/tests/embedded_client.rs`, and `crates/htap-convert/tests/materialization.rs`. Explicitly deferred: partition lifecycle DDL (`ALTER TABLE ... ADD/DROP/REORGANIZE PARTITION`), partition split/merge/drop, multi-partition conversion and movement, hash tablets, distributed serving/failover, joins, CTEs, windows, expressions / aliases if rejected / aggregate ordering in `ORDER BY` and broad MySQL ordering (simple unqualified source/projected column `ORDER BY` is implemented for `AnalyticSelect` with ASC/DESC and NULLS FIRST/LAST/default policy, global deterministic tie-break), `LIMIT`/`OFFSET`, `HAVING`, `OR`/`NOT`/arithmetic/casts, `AVG` and `DISTINCT` aggregates, compound AND pushdown beyond one leaf, `!=` pushdown, vectorized aggregation / operator pipelines, hash buckets / tablet sharding, multi-tablet/distributed scans, quotas/spill/cancellation, DataFusion/Arrow, full MySQL breadth, MySQL wire compatibility, the `htapd` daemon/protocol, sessions/`BEGIN`/`COMMIT`/`ROLLBACK`, and non-PK DML (`UPDATE`/`ALTER`/`DROP`). |
| Phase 4 — HTAP conversion | `Complete (local MVP)` | Built the local partition-scoped row-to-column conversion engine (`htap-convert`) with durable columnar manifest envelope (`HTAPTBM1`), deterministic four-phase state machine (`SnapshotPinned` -> `SegmentsWritten` -> `ReadyToPublish` -> `Column`), atomic per-tablet manifest and catalog publication, rowstore-authoritative base-plus-delta overlay via converter APIs (`read_column_partition` and projection-aware compact reads `read_column_partition_compact`, verified in `crates/htap-convert/tests/materialization.rs`) and server-root `<root>/colstore` analytical scans with direct SegmentReader pushdown optimization for the compact base path, and online point writes and point reads on converting and columnar partitions. Covered by tests in `crates/htap-convert/tests/tablet_manifest.rs`, `crates/htap-convert/tests/materialization.rs`, `crates/htap-sql/tests/route.rs`, `crates/htap-server/tests/local_server.rs`, and catalog recovery conversion tests (`crates/htap-catalog/tests/catalog_recovery.rs`: `test_conversion_metadata_and_manifest_roundtrip_and_reopen`, `test_invalid_conversion_combinations`, `test_invalid_column_manifest_and_paths`, `test_conversion_stale_cas`). Reverse `Column -> Row` conversion is not implemented and not claimed. Explicitly deferred: reverse `Column -> Row` conversion, delete vectors, physical rowstore reclamation, background compaction, compound AND pushdown beyond one leaf, `!=` pushdown, vectorized aggregation / operator pipelines, and full multi-tablet/distributed partition/table conversion semantics. |
| Phase 5 — Data movement | `Complete (local MVP)` | Built single-node data movement engine (`htap-movement`) and server integration (`LocalServer::data_mover` / `LocalServerDataMover`). Supports durable job lifecycle tracking (`HTAPJOB1`), CSV and JSONLines import streaming, export partition materialization (exports materialize full logical partition before writing), batching and atomic commit replay, and tablet snapshot clone/verify/repair with catalog CAS reconciliation. Covered by tests in `crates/htap-movement/tests/jobs.rs`, `crates/htap-movement/tests/import_export.rs`, `crates/htap-movement/tests/tablet_simulation.rs`, and `crates/htap-server/tests/local_server.rs` (`test_server_data_mover_integration`, `test_server_data_mover_clone_verify_repair`). Distributed multi-node movement, SQL COPY grammar, and background replication are deferred. |
| Phase 6 — Distribution and coordination | `Complete (local MVP)` | Built local coordination, leadership fencing, deterministic placement, and replica activation MVP (`htap-coord`). Implemented synchronous `Coordinator` trait and durable `LocalCoordinator` backed by `HTAPCRD1` binary envelopes, sorted membership, strictly monotonic fencing tokens, and coordinator-fenced catalog CAS (`fenced_catalog_compare_and_set`). Implemented pure deterministic placement planner (`plan_placement`) and coordinator-fenced staging and local activation simulation (`stage_placement_addition`, `activate_placement_addition`, `activate_placement_plan`). Covered by integration tests in `crates/htap-coord/tests/local_coordinator.rs`, `crates/htap-coord/tests/placement_movement.rs`, movement tablet simulation tests in `crates/htap-movement/tests/tablet_simulation.rs`, and server/movement integration tests in `crates/htap-server/tests/local_server.rs`. Local same-root exclusive ProcessLock/cross-process contention rejection is implemented; explicitly deferred: direct `CatalogStore` CAS and older movement repair APIs bypass coordinator fence; no Raft/`openraft`, ZooKeeper backend, watches/locks/KV semantics, distributed/cross-node exclusion/consensus, remote physical movement, leader handoff, ongoing replication, capacity/rack placement, or live rebalance are implemented. |
| Phase 7 — Hardening, benchmarks, local MVP | `Complete (local evidence MVP)` | Built local microbenchmark suite (`htap-bench`, `benches/local_mvp.rs`) measuring rowstore point lookups (`rowstore/point_get_stable_snapshot`), colstore zone-map scans (`colstore/equality_zone_map_scan`, verifying 99% skip), conversion (`convert/local_converter_row_to_column`), CSV import (`movement/fixed_csv_import`), coordinator placement planning (`coord/placement_planning`), and coordinator leadership fenced CAS (`coord/leadership_fenced_cas`). Deferred: `htapd` daemon, MySQL wire protocol, network endpoints, Docker image/Compose, ZooKeeper/Raft backends, physical power-loss fsync testing, and TPC-C/TPC-H compliance. |
